3. 기능과 시험

기획서의 기능 6가지와 시험 52개입니다.

기능내용
데이터 올리기엑셀 시트 3장을 읽고 날짜 형식(엑셀 일련번호·점·한글)을 맞춥니다. 틀린 줄은 버리지 않고 「확인할 것」으로 알립니다.
주간 부하 히트맵부문 × 주 표에 필요 인원을 쓰고 여유·적정·빠듯·부족을 색과 숫자로 보여 줍니다.
사유 설명칸을 누르면 그 주를 채운 기종·단계와 지난주보다 늘고 준 원인을 문장으로 설명합니다.
부문 추이 · 간트선택한 부문의 주별 부하와 가용선을 꺾은선으로, 기종별 단계 일정을 간트로 그립니다.
가정 비교가정 4종을 쌓고 사유 메모를 붙입니다. 부문별 전→후 표, 전후 꺾은선, 일정 전후 간트를 보여 줍니다.

6. 한계와 남은 일

  • 사내 로드맵 시스템 자동 연동은 하지 않습니다(내려받은 엑셀을 올림).
  • 부하기준(단계·부문별 투입 인원)을 자동으로 정하지 않습니다 — 부서 협의로 표를 정합니다.
  • 「매뉴얼 AI Chatbot」(기획1)은 보안 문서·이미지 인식이 핵심이라 이번 과정에서는 DAY4 RAG 실습 예제로 다룹니다.
  • 업무 자료는 지금처럼 브라우저 안에서만 처리합니다. 로그인 DB 에는 「누가 쓸 수 있는가」와 게시판 글만 있습니다.
  • 로그인 뒤 화면(게시판 · 관리 · 첫 화면 고르기)은 실제 계정으로 눌러 보지 않았습니다. 가입 → 사용 신청 → 승인 → 게시판 글쓰기 확인은 기획자와 관리자 몫입니다.
  • 독립 운영까지 남은 것: 본인 Supabase 프로젝트에 auth.sql · board.sql · site.sql 실행 → js/auth-config.js 의 url · anonKey 교체 → 다시 배포(supabase/README.md)
